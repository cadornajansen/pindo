# D4 — AI Tutor

## Flow

`MainWindow → foreground context → UiAutomationService → TutorService → ITutorModel
→ AssemblyAiTutorModel → validated TutorResponse → UIA runtime-ID resolution → HighlightOverlay`

Ctrl+Space in Excel asks `How do I create a PivotTable?`. UIA runs on a thread-pool
thread so it does not block WPF. Up to 40 enabled, visible, named TabItems are sent;
cell contents, screenshots, bounds, HWNDs and UIA runtime IDs are not sent.
Runtime IDs remain local and bind the model's request-scoped identifier to a real
element. The element's name, automation ID, visibility, enabled state and fresh
bounds are checked after the network request. A changed foreground window,
process or title prevents highlighting. There is no hardcoded Insert fallback.

Existing D1 foreground logging, D2 lookup/overlay classes, and D3 on-demand local
capture remain. Capture runs alongside the tutor and is never sent to the model.
The instruction appears in Pointly's status text and log without stealing focus.

## JSON contracts

Request example (actual titles, names and IDs come from UIA):

```json
{
  "userQuery": "How do I create a PivotTable?",
  "foregroundProcessName": "EXCEL",
  "windowTitle": "Book1 - Excel",
  "elements": [
    { "id": "element-3", "name": "Insert", "automationId": "TabInsert", "controlType": "ControlType.TabItem" }
  ],
  "currentContext": "Initial step. Visible UIA tabs only; no earlier tutoring step is available."
}
```

Response example (illustrative, not a measured model response):

```json
{
  "instruction": "Open the Insert tab.",
  "targetElementId": "element-3",
  "annotationType": "rectangle",
  "expectedNextState": "The Insert ribbon is visible.",
  "confidence": 0.95
}
```

Every response property is required. Unknown properties, unknown/integer
annotations, prose, fenced JSON, missing fields, incomplete completions, unknown
target IDs and invalid confidence values are rejected. Confidence below 0.5 does
not highlight. Expected state is descriptive only; D4 does not observe completion.

## Gateway

Uses `POST https://llm-gateway.assemblyai.com/v1/chat/completions` with the raw
`ASSEMBLYAI_API_KEY` environment value in the Authorization header. No SDK or new
package is needed: HttpClient and System.Text.Json are built into .NET.
`response_format.type=json_schema`, `strict=true` requests structured output;
the response in `choices[0].message.content` is deserialized and validated locally.
Reference: https://www.assemblyai.com/docs/llm-gateway/structured-outputs

`POINTLY_TUTOR_MODEL` overrides the default `gpt-5.6-luna`. Pointly calls
`GET /v1/models` once per process and refuses a configured primary or fallback
model that is unavailable or lacks `response_format`. The live lookup verified
that Luna is currently available and JSON-schema capable.

Set `POINTLY_TUTOR_FALLBACK_MODEL` to one different, JSON-capable Gateway model
to opt into one server-side fallback, for example `gemini-2.5-flash-lite`.
Pointly sends `fallback_config.retry=false`, disabling the Gateway's default
500 ms retry. A fallback is never enabled unless explicitly configured.

HTTP timeout is 20 seconds; the invocation cancellation deadline is 30 seconds.
Another Ctrl+Space cancels the active tutor, and closing Pointly cancels it too.
On HTTP 429, Pointly records Retry-After and declines to send another request
until that window expires; it never spins or auto-retries. The UI gives the
remaining wait time. For every non-2xx response, the log records the sanitized
response body and Retry-After, X-RateLimit, RateLimit, and request-ID headers.
It redacts the configured API key and never logs the request body.

## Manual test

1. Close the previously running Pointly instance so it releases Ctrl+Space.
2. In PowerShell, with ASSEMBLYAI_API_KEY already set securely in that environment:

   ```powershell
   $env:POINTLY_TUTOR_MODEL = 'gpt-5.6-luna'
   dotnet build Pointly.sln -c Debug
   dotnet run --project Pointly.App/Pointly.App.csproj -c Debug --no-build
   ```

3. Open an Excel workbook with the Home tab selected and the ribbon visible.
4. Focus Excel and press Ctrl+Space once. Keep Excel foreground while waiting.
5. Expect the actual Insert tab to receive the existing click-through rectangle.
   Return to Pointly to read the instruction, target, confidence, expected state,
   UIA collection, model request, target resolution and hotkey-to-highlight timings.
6. Repeat, pressing Ctrl+Space while the model is pending: expect cancellation,
   no late highlight, and a responsive app. Retry once the invocation finishes.
7. Repeat while switching to a different foreground window before the response:
   expect no highlight. With an invalid/missing key, expect a logged failure.
8. Verify Ctrl+Space in Chrome still logs the foreground window and local capture.

## Verification and limits

- Debug build: zero warnings/errors.
- Temporary external harness: 14 contract/failure checks passed, including HTTP
  401/429 and cancellation. An additional HTTP timeout check passed. Live UIA
  checks resolved Insert and rejected an invented runtime ID. The harness is
  outside the repository; no test framework or test project was added.
- Live provider probe with Excel's actual UIA candidates: HTTP 200. Luna selected
  Insert at 0.99 confidence. UIA collection was 288 ms, model verification plus
  request was 2,708 ms, and local runtime-ID resolution was 216 ms.
- The full Pointly overlay remains a manual test: focus Excel and press Ctrl+Space.
  The current app has been rebuilt and relaunched for this check. No 429 occurred
  on the successful live probe, so it produced no 429 body or rate-limit headers.
- D4 selects a first tab only. No multi-step state tracking, selected-tab awareness,
  screenshot reasoning, voice or automatic application actions are implemented.
- UIA's synchronous provider calls cannot be interrupted midway by a cancellation
  token. Cancellation is checked between calls; a stalled provider can delay
  completion beyond the deadline. A single in-flight invocation prevents piling
  up workers, and WPF remains responsive.
- Foreground checks occur before showing the highlight. D4 does not continuously
  track a target after highlighting; invoke again after later window movement.
