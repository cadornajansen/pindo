# D5 — Multimodal Grounding

## Flow

`MainWindow → foreground context → compact UI Automation candidates → TutorService`

- A confident, unique tutor-selected UIA target resolves to fresh physical bounds and goes directly to `HighlightOverlay`. The log records `Route=UIA cloud-grounding=not-invoked`.
- An unavailable, ambiguous, unresolved, or low-confidence UIA target routes the existing D3 capture to `GuiGroundingService → IGuiGroundingModel → configured provider`.
- A validated normalized point or box is converted to screenshot pixels, then physical screen pixels, then passed to the existing DPI-aware overlay.

OpenRouter with `google/gemini-3.8-flash` is the current default grounding provider.
`POINTLY_GROUNDING_PROVIDER=openrouter|nova` selects a provider explicitly. An
empty or absent value selects OpenRouter; any other value fails vision grounding
with a configuration error. There is no automatic provider fallback. Future
grounding models belong behind `IGuiGroundingModel`, without changing the UIA
route or coordinate conversion.

The temporary query remains `How do I create a PivotTable?` for Excel. Other
applications use `Where do I add text?` for the D5 manual test.

## Bedrock and Nova (explicit benchmark provider)

The provider uses `AWSSDK.BedrockRuntime` and the Bedrock Runtime `Converse` API.
It sends one PNG image content block and one text content block in a user message.
The SDK accepts raw image bytes; Pointly does not base64-encode them itself.
The implementation follows the official [Converse API examples](https://docs.aws.amazon.com/bedrock/latest/userguide/conversation-inference-examples.html)
and [Nova model capability table](https://docs.aws.amazon.com/nova/latest/userguide/models.html).

When Nova is explicitly selected, its default model is the US cross-region inference profile
`us.amazon.nova-2-lite-v1:0`, a current fast multimodal Nova model. Override it
with `POINTLY_VISION_MODEL`. Pointly maps the earlier documented direct ID
`amazon.nova-2-lite-v1:0` to this profile so existing D5 configurations keep
working. Region resolution is:

1. `POINTLY_BEDROCK_REGION`
2. `AWS_REGION`
3. `AWS_DEFAULT_REGION`
4. `us-east-1`

The default `AmazonBedrockRuntimeClient` uses the normal AWS SDK credential
resolution chain. Pointly contains no access keys. Configure credentials through
standard AWS environment variables, a shared AWS profile, or an attached AWS
role, and grant permission for `bedrock:InvokeModel` on the configured model.

Pointly defines a `pointly_grounding` Converse tool with the response JSON
schema and forces Nova to call that tool exactly once. Nova 2 Lite rejects the
newer `strict` tool field, but its forced tool choice uses schema-constrained
output. Pointly reads only the returned `toolUse.input`; it never extracts a box
from prose or fenced output. Typed local validation remains the final gate before
coordinates can reach the overlay.

Response shape:

```json
{
  "instruction": "Select Text in the left toolbar.",
  "targetLabel": "Text",
  "boundingBox": { "x1": 18, "y1": 240, "x2": 95, "y2": 300 },
  "confidence": 0.92,
  "description": "Text tool in the left navigation"
}
```

Coordinates use a 0–1000 image-relative space. All four values must be finite
and within that range, `x2 > x1`, and `y2 > y1`. Confidence must be within 0–1
and at least 0.65 before the overlay can move. Required text fields, size limits,
unknown JSON properties, and malformed JSON are also checked.

## Coordinates and DPI

For each axis, Pointly applies:

`normalized / 1000 → captured-image pixels → D3 physical window rectangle`

The image-to-window ratio handles small differences between capture surface and
window dimensions. The resulting physical screen rectangle includes the window's
screen offset. `HighlightOverlay` performs the existing physical-pixel-to-WPF-DIP
conversion, preserving D3's per-monitor DPI behavior.

## Lifetime, failure handling, and timing

The D3 BGRA buffer and the in-memory PNG are cleared after every invocation. No
new screenshot writer was added; files are created only when the existing
`POINTLY_CAPTURE_DEBUG_DIR` path is explicitly enabled. Bedrock states that
Converse does not store submitted content.

The AWS client timeout is 45 seconds and the complete hotkey invocation deadline
is 60 seconds. Ctrl+Space during an invocation cancels it. AWS, capture, timeout,
JSON, validation, and context-change failures produce a status message and do not
crash Pointly. Logs separately record screenshot acquisition, PNG preparation,
AWS request, coordinate conversion, vision-to-highlight, and complete hotkey
latencies. Provider failures log status, AWS error code, and request ID, without
credentials, image data, or arbitrary response content.

## Manual test

For the default OpenRouter route, set the key in the same PowerShell session
that launches Pointly. No provider override is required:

```powershell
dotnet build Pointly.sln -c Debug
$env:OPENROUTER_API_KEY = '<local credential>'
Remove-Item Env:POINTLY_GROUNDING_PROVIDER -ErrorAction SilentlyContinue
$env:POINTLY_DEBUG_FORCE_VISION = 'true'
dotnet run --project Pointly.App/Pointly.App.csproj -c Debug --no-build
```

The key is read only when a vision request is made. Pointly checks its process
environment first, then the current Windows user's environment. This also works
when Pointly was launched by an IDE that started before the user variable was set.
If the key is missing from both locations, Pointly
remains open and logs `GroundingFailure=MissingOpenRouterApiKey`, without sending
a request. `POINTLY_OPENROUTER_MODEL` overrides the default Gemini model.
Never add credentials to a project file, source file, or this document.

For a Nova benchmark, set `POINTLY_GROUNDING_PROVIDER=nova` before launch and
configure AWS credentials through the normal SDK resolution chain (environment,
profile, or role). `POINTLY_VISION_MODEL` and `POINTLY_BEDROCK_REGION` retain
their existing Nova overrides. Nova is retained as an explicit benchmark or
manual fallback provider, with no automatic switch from OpenRouter on failure.

### Forced CapCut or Canva check

1. Use the Debug build and set `POINTLY_DEBUG_FORCE_VISION=true` before launch.
2. Open CapCut or Canva with its editor and Text control visible.
3. Focus the editor and press Ctrl+Space once; keep it foreground.
4. Pointly captures that window and asks the selected provider `Where do I add text?`.
5. Expect the existing overlay around the visible Text control.
6. Return to Pointly and confirm logs for the forced route, acquisition,
   preparation, AWS request, conversion, target, confidence, and totals.
7. Press Ctrl+Space again during a request to verify cancellation and no late
   highlight.

`POINTLY_DEBUG_FORCE_VISION` is compiled out of Release behavior and is not a
production feature.

### Excel regression check

1. Stop Pointly, remove the override, and start it again:

   ```powershell
   Remove-Item Env:POINTLY_DEBUG_FORCE_VISION -ErrorAction SilentlyContinue
   dotnet run --project Pointly.App/Pointly.App.csproj -c Debug --no-build
   ```

2. Open Excel with Home selected and the ribbon visible.
3. Focus Excel and press Ctrl+Space.
4. Expect the Insert tab to be highlighted through UIA.
5. Confirm the log contains `Route=UIA cloud-grounding=not-invoked` and contains
   no `Route=VISION` telemetry for that invocation.

## OpenRouter grounding and Nova comparison

OpenRouter is the default. Set `POINTLY_GROUNDING_PROVIDER=nova` to use
`BedrockNovaVisionModel` for a comparison. The
OpenRouter key is read from `OPENROUTER_API_KEY` at request time (process, then
current Windows user). The default
model is `google/gemini-3.8-flash`, overridable with
`POINTLY_OPENROUTER_MODEL`. No key is stored in the repository.

OpenRouter receives one in-memory PNG data URL and a text instruction through
`POST https://openrouter.ai/api/v1/chat/completions`. Pointly requests a strict
`json_schema` response containing nullable `targetLabel`, `point`,
`boundingBox`, and `description`. It asks for low reasoning effort and caps the
reply at 1,024 tokens, including Gemini's reasoning tokens. OpenRouter returns no confidence in this schema, so Pointly
does not assign one. Nova still returns its confidence and box through the
existing forced Bedrock tool. The service rejects malformed, oversized,
non-finite, out-of-range, or missing targets. If a model returns both a point
and a box, the point must lie inside the box; Pointly highlights the box. It rejects Nova results
below 0.65 confidence. A point renders as a small ring; a box uses the existing
rectangle. Neither provider can click the target.

For one comparable manual run, start Pointly from PowerShell with the chosen
provider and a DEBUG-only query override:

```powershell
$env:POINTLY_GROUNDING_PROVIDER = "openrouter" # or "nova"; omit for default OpenRouter
$env:POINTLY_OPENROUTER_MODEL = "google/gemini-3.8-flash"
$env:POINTLY_DEBUG_FORCE_VISION = "true"
$env:POINTLY_DEBUG_GROUNDING_QUERY = "Where do I add text?"
dotnet run --project Pointly.App/Pointly.App.csproj -c Debug --no-build
```

Set `OPENROUTER_API_KEY` in that shell for OpenRouter, or configure normal AWS
credentials for Nova. Focus the target application before Ctrl+Space. Change
`POINTLY_DEBUG_GROUNDING_QUERY` and restart Pointly for each target. Use the
same five tasks on each provider, three runs per task:

An invalid `POINTLY_GROUNDING_PROVIDER` produces a configuration failure on a
vision request and never substitutes another provider. The normal Excel UIA
route still bypasses both providers.

| App | Target prompts |
| --- | --- |
| CapCut | Where do I add text?; Where is Audio?; Where are Transitions?; Where is Export?; Where do I import media? |
| Canva | Where is Text?; Where are Elements?; Where are Uploads?; Where is Share?; Where is the visible Download or Export control? |

Record provider, model, target, correct target (yes/no), `ProviderRequestMs`,
`TotalMs`, visual alignment (yes/no), and `FailureReason`. The telemetry logs
only provider, model, timings, target geometry type, success, and a safe failure
category. It does not log image data or provider response bodies. Canva and
live overlay alignment still require separate manual runs in the target app.

One unchanged 1920×1020 CapCut foreground-window frame was sent for the same
five tasks three times per provider. All 30 responses passed local validation

| Audio | 4,743 ms | 2,559 ms | Both aligned with Audio. |

## Verification and limits

- `dotnet build Pointly.sln -c Debug`: zero warnings and zero errors.
- An external temporary harness passed eleven response-validation, coordinate,
  legacy-model-migration, structured-tool-document, and forced-tool-schema
  checks; no test project was added to the repository.
- A live read-only Excel route check collected 40 candidates in 566 ms. The
  existing AssemblyAI tutor selected `Insert` at 0.99 confidence in 2,454 ms,
  and its real UIA runtime ID resolved unambiguously in 248 ms. The decision was
  `UIA; AWS not invoked`.
- A separate live local capture probe measured 411 ms for D3 acquisition, 309 ms
  for in-memory PNG preparation, and 1 ms for normalized-to-screen conversion.
- The first user-run Nova request authenticated but Bedrock rejected the former
  direct model ID with HTTP 400 `ValidationException`. The provider now uses the
  documented US inference profile. The next request reached Nova in 6,654 ms but
  exposed prompt-only JSON variability. A subsequent request confirmed Nova 2
  Lite rejects the `strict` field, so the provider now uses its supported forced
  schema tool output.
- The final CapCut run completed end to end: zero UIA candidates triggered vision,
  Nova selected `Text` at 0.95 confidence, and the existing red overlay appeared.
  Screenshot acquisition took 150 ms, PNG preparation 36 ms, AWS 3,386 ms,
  coordinate conversion less than 1 ms, vision-to-highlight 3,554 ms, and total
  hotkey-to-highlight 3,639 ms.
- The D5 test query is temporary and fixed. There is no voice, step verification,
  continuous capture, autonomous input, Jev, or D6 behavior.
- The model can still identify the wrong visible control. The 0.65 gate and strict
  geometry checks prevent malformed or explicitly uncertain results from moving
  the overlay, but they cannot prove semantic correctness.
- A foreground title change while waiting rejects the result. The highlight does
  not continuously follow later window movement.
