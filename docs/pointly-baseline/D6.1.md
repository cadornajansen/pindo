# D6.1 — Local click verification

After either the UIA or vision path highlights one target, Pointly starts one
temporary `ClickVerificationService` session. A `WH_MOUSE_LL` hook observes real
left-button presses and always passes them to the next hook; it never controls
the mouse or blocks the application. Injected presses are ignored. The hook is
removed on a hit, cancellation, replacement, or application shutdown.

The target and hook event both use physical screen coordinates. A box accepts
its inclusive bounds. A point accepts clicks within a 30-physical-pixel radius
of its center. Negative coordinates on secondary monitors are valid. A miss
logs `VerificationClick Result=Miss` and leaves the overlay and session active.
A hit logs `VerificationClick Result=Hit` and
`VerificationCompleted VerificationDurationMs=...`, removes the hook, hides the
overlay, and shows `Step completed.` No model call is made for verification.

The current foreground HWND is checked when each click arrives. If it differs
from the highlighted window, the session is cancelled. There is no continuous
window movement or application-state tracking in D6.1.

## Manual check

1. Build and run Pointly. In Excel, leave the ribbon visible, focus Excel, and
   press Ctrl+Space. Confirm `Route=UIA` and `VerificationStarted TargetType=Box`.
2. Click another visible Excel control outside the Insert highlight. Confirm
   `VerificationClick Result=Miss`; the highlight remains. Click inside Insert.
   Confirm `Result=Hit`, `VerificationCompleted`, and `Step completed.`
3. For the D5 vision path, use the existing DEBUG-only forced-vision settings
   with the same provider configuration as before. A returned box follows the
   same miss-then-hit behavior. A returned point shows a ring; click clearly
   more than 30 physical pixels from its center to verify a miss, then click
   within that radius to verify completion.
4. Start another request before clicking the highlighted target. Confirm
   `VerificationCancelled Reason=NewRequest` and that a late click cannot
   complete the old session. Repeat several times to check for duplicate events.
5. Select `POINTLY_GROUNDING_PROVIDER=nova` explicitly for the existing Nova
   benchmark. With no provider override, OpenRouter remains the vision default.

Run `dotnet test Pointly.sln -c Debug` for pure geometry and session-state tests.
The tests do not synthesize mouse input or call AI providers.

This verifies only whether a user clicked the highlighted location. It does
not verify that the application changed state or generate the next lesson step.
