# D6.2 deterministic walkthrough demo

In a Debug build, set `POINTLY_DEBUG_WALKTHROUGH=excel-pivottable` in the environment that launches Pointly. With Excel foreground, Ctrl+Space starts the three-step PivotTable walkthrough: Insert tab, PivotTable control, then OK in the Create PivotTable dialog. Targets are resolved afresh for each step through the existing UIA-first path and vision fallback. The definition contains no coordinates or provider identifiers.

```powershell
$env:POINTLY_DEBUG_WALKTHROUGH = "excel-pivottable"
dotnet run --project Pointly.App/Pointly.App.csproj -c Debug --no-build
```

Open a workbook with a selected data range before invoking the hotkey. Click away from the highlight to observe a miss; the same step remains active. Click the highlighted target to advance. After the final hit, Pointly shows “Walkthrough completed.” Press Ctrl+Space again to start a new session. To test standalone grounding, remove `POINTLY_DEBUG_WALKTHROUGH` from the launch environment and restart Pointly; the normal Ctrl+Space behavior remains available.

The demonstration verifies clicks only. It does not check Excel's resulting state or verify entered data. A different Excel version, ribbon layout, or PivotTable dialog may cause target resolution to fail; Pointly stops rather than skipping the step. The current click verifier accepts the foreground window recorded at click time, including when that click closes a dialog. The walkthrough does not make an AI call after a miss; each new step uses the existing target-resolution route.
