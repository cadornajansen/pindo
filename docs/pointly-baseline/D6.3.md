# D6.3 action and UIA state verification

The existing `excel-pivottable` DEBUG walkthrough remains available. A second DEBUG demo uses Excel's Microsoft search field, which exposes a UI Automation value in the tested Excel build:

```powershell
$env:POINTLY_DEBUG_WALKTHROUGH = "excel-search"
dotnet run --project Pointly.App/Pointly.App.csproj -c Debug --no-build
```

With Excel foreground, press Ctrl+Space. The three predefined steps are:

`POINTLY_DEBUG_FORCE_VISION=true` may remain set for a grounding benchmark. It can force the click step through vision, but the text-entry step always uses UIA because its value must be read from the actual input. The log says when the debug override is ignored. For a pure UIA-first walkthrough test, remove `POINTLY_DEBUG_FORCE_VISION` before launching Pointly.

1. Click Microsoft search. A brief UIA check must confirm that the identified search field has keyboard focus.
2. If Pointly is in front, click Excel's search field again. Type exactly `PivotTable` and wait until the status changes to Step 3. The verifier observes typing activity but does not retain keys; it reads only the identified UIA control and requires an exact value match.
3. With Excel's search field focused, press Enter. The keyboard hook verifies the real key-down event; an incorrect key leaves the step active.

For the click step, try a miss before clicking the highlight. For the text step, wait with an empty field, then type the word. For the key step, press Tab before Enter. Press Ctrl+Space during any step to cancel and restart. The search demo does not change workbook data. Remove `POINTLY_DEBUG_WALKTHROUGH` and restart Pointly to test standalone grounding.

Opening Pointly's log window temporarily pauses keyboard/text verification; it does not cancel the walkthrough. Return to the Excel search field to continue. If the original Excel window is destroyed, verification cancels safely.

State checks poll every 150 ms for at most 2 seconds. A missing expected state fails the walkthrough rather than silently advancing. Text entry requires a UIA-readable target; it does not fall back to screenshot interpretation. Other Excel versions may expose different UIA names, patterns, or focus behavior. No typed value, keystroke sequence, or screenshot is logged by these verifiers.
