# D7 — Voice adapter

D7 wraps the existing Pointly request and walkthrough paths. ElevenLabs receives microphone audio for transcription and user-facing instruction text for speech. Pointly still owns tutor reasoning, UI Automation, vision fallback, overlays, walkthrough progression, and D6 verification.

## Configuration

Set `ELEVENLABS_API_KEY` in the environment that launches Pointly. The app starts and non-voice features work without it; a voice request then fails with `MissingElevenLabsApiKey`. Do not place the key in source or a tracked configuration file.

Voice mode is deliberately opt-in while the existing Ctrl+Space and DEBUG walkthrough workflows are in use:

```powershell
$env:ELEVENLABS_API_KEY = "<your key>"
$env:POINTLY_VOICE_MODE = "true"
dotnet run --project Pointly.App/Pointly.App.csproj -c Debug
```

Restart Pointly after setting variables because an already-running process cannot inherit later shell changes. Optional overrides are `POINTLY_STT_MODEL` (default `scribe_v2_realtime`), `POINTLY_TTS_MODEL` (default `eleven_flash_v2_5`), and `POINTLY_VOICE_ID` (default `JBFqnCBsd6RMkjVDRZzb`).

## Flow

Ctrl+Space starts the default Windows microphone at 16 kHz, 16-bit mono PCM. `WindowsAudioCapture` streams 100 ms chunks in memory. `ElevenLabsSpeechToText` connects to Scribe realtime over WebSocket and sends base64 audio chunks. Partial transcript events update the status line only. A second Ctrl+Space stops capture and sends a manual commit; only ElevenLabs' `committed_transcript` is passed to the existing `GuideForegroundAsync` path. No language code is fixed, so ElevenLabs can detect English, Filipino, or mixed speech.

For the supported Excel PivotTable demo, a final transcript mentioning “PivotTable” starts the existing predefined PivotTable walkthrough. Each step still resolves its target through the existing UIA-first tutor path, and only D6 verification advances it; the voice adapter does not generate steps. Other final transcripts use the existing one-shot `GuideForegroundAsync` query path. After UIA or vision resolves a target, Pointly shows the existing overlay and starts D6 verification. `ElevenLabsTextToSpeech` streams the user-facing instruction as `pcm_16000` from the HTTP TTS endpoint. `WindowsAudioPlayback` buffers and plays the chunks without a temporary file. Walkthrough instructions are spoken once after each step resolves.

Voice state is `Idle → Listening → Finalizing → Processing → Speaking → Idle`. Ctrl+Space while processing cancels. Ctrl+Space while speaking stops playback and starts listening again. Starting a new session cancels the previous one. A cancelled or replaced STT final cannot launch a request. Microphone, WebSocket, network stream, and playback are disposed when their operation ends. Audio, credentials, and transcripts are not written to logs or disk; partial transcript is visible in the status line. Telemetry records stage names, character counts, and timings.

The voice session retains the foreground window selected when listening began. If that window loses foreground before the final query is processed, Pointly cancels guidance rather than pointing into a different app. Voice is explicitly activated; there is no background listening or wake word.

## Manual checks

1. Open Excel, set the key and `POINTLY_VOICE_MODE=true`, launch Pointly, and keep Excel foreground. Press Ctrl+Space, say “How do I create a PivotTable?”, then press Ctrl+Space again. Check that a partial appears, the final transcript is visible while processing, and the existing PivotTable walkthrough uses UIA-first resolution to highlight Insert and speak the instruction once. Click the highlighted targets to verify the next instruction is spoken only after D6 confirms each action.
2. While speech plays, press Ctrl+Space. Playback should stop and the status should become “Listening...”. Speak another question and stop with Ctrl+Space.
3. For a walkthrough, also set `POINTLY_DEBUG_WALKTHROUGH=excel-pivottable` before launching. Ctrl+Space starts the deterministic Excel steps. Each instruction should be spoken once, and only the correct D6 click should advance. Clear the walkthrough variable to test a normal voice query.
4. Cancel during listening, processing, and speaking. Repeated invocations should have no duplicate microphone or playback sessions.
5. Unset `ELEVENLABS_API_KEY` and restart. Non-voice Ctrl+Space continues to work when voice mode is off; voice mode reports the missing key safely.

Run `dotnet build Pointly.sln -c Debug` and `dotnet test Pointly.sln -c Debug` for local verification. Live ElevenLabs and microphone behavior requires the user's API key, microphone permission, speakers, and a foreground application; automated tests use fakes.

## Limits

The user manually ends an utterance with Ctrl+Space; no autonomous VAD turn-taking or simultaneous listening during a walkthrough is implemented. PivotTable recognition is a narrow demo mapping, not general spoken intent parsing or AI-generated planning. Other one-shot tutor queries highlight one target. Exact network latency and English/Filipino transcription quality require live testing on the target machine.

## Diagnosing an empty realtime transcript

The STT-only investigation found that the old `DeviceNumber=0` input was the microphone array, and that Windows' current multimedia default was the same array with endpoint mute enabled. The separate communications microphone was unmuted. This is evidence of a silent/wrong-input risk, not proof of the samples sent during an earlier run: that run had no audio-level telemetry. Pointly does not unmute devices or change Windows preferences.

Capture now asks WinMM for the current preferred recording device using `DRVM_MAPPER_PREFERRED_GET` each time listening starts. It logs that selected device and index in DEBUG, plus the Windows multimedia default's friendly name and mute state. Index zero is no longer assumed to mean default. The selected device is fixed for one recording; switching the Windows default takes effect on the next activation. No selector UI was added.

The format before and after this fix is `WaveFormat(16000, 16, 1)`: signed PCM16, little-endian, mono. NAudio passes that format to `waveInOpen`; a successful open yields this application format or the device rejects it. The log describes the negotiated **capture output**, not the microphone hardware's native mix rate. WinMM can handle format conversion. No application resampler was needed or added. Buffers are normally 100 ms / 3200 bytes; a final buffer can be shorter.

The current [ElevenLabs realtime reference](https://elevenlabs.io/docs/api-reference/speech-to-text/v-1-speech-to-text-realtime) and [server streaming guide](https://elevenlabs.io/docs/eleven-api/guides/how-to/speech-to-text/realtime/server-side-streaming) specify:

```text
wss://api.elevenlabs.io/v1/speech-to-text/realtime?model_id=scribe_v2_realtime&audio_format=pcm_16000&commit_strategy=manual
xi-api-key: <environment credential; never logged>
```

Each PCM chunk is sent immediately after `session_started`:

```json
{"message_type":"input_audio_chunk","audio_base_64":"<PCM bytes encoded in memory>","sample_rate":16000,"commit":false}
```

After Stop completes the capture queue and every already-delivered chunk has been sent, send one separate control message:

```json
{"message_type":"input_audio_chunk","audio_base_64":"","sample_rate":16000,"commit":true}
```

This empty payload is an intentional manual commit, never a zero-length data chunk. The receive loop stays alive until a committed transcript, error, cancellation or 10-second finalization timeout. The old final-nonempty-chunk `commit:true` shape was also supported, and its normal send path already drained the queue. There was no proven premature normal close. The changes make ordering explicit, remove one-chunk latency, report queue overflow instead of silently discarding audio, and retain early automatic commits without terminating capture. See [commit behavior](https://elevenlabs.io/docs/eleven-api/guides/how-to/speech-to-text/realtime/transcripts-and-commit-strategies).

DEBUG boundary logs include:

- `MicrophoneDevice`, `WindowsDefaultCapture`, `Muted`, `RequestedFormat`, `ActualFormat`.
- `MicAudio Chunk=... Bytes=... Peak=... Rms=...` for the first three callbacks and then every twentieth. Peak and RMS are normalized to full-scale PCM (0–1).
- `MicSummary Chunks=... Bytes=... PeakMax=... RmsAverage=... DroppedChunks=...`. RMS is computed across all samples, weighted by chunk size.
- `SttAudioChunkSent ChunkCount=... Bytes=... TotalBytes=...`, similarly throttled.
- `SttCommitSent QueuedAudioDrained=true`, followed by `SttAudioSummary ChunksSent=... BytesSent=...` on exit. Counts exclude the empty commit.
- Safe event names: `session_started`, `warning`, `error`, `partial_transcript`, `committed_transcript`. Warnings use fixed categories; errors use allowlisted codes. Transcripts only report character counts.
- `SpeechFinalEmpty CapturedChunks=... CapturedBytes=... SentChunks=... SentBytes=... Peak=... Rms=... DroppedChunks=...`. An empty transcript returns to Idle with a visible microphone-check message and makes no tutor/TTS call.

Interpretation:

| Observation | Boundary to investigate |
| --- | --- |
| No microphone callbacks / `NoMicrophoneAudio` | Capture start, device or permission |
| Captured chunks but no sent chunks | Session readiness, send failure or queue error |
| Sent counts match captured counts, Peak/RMS near zero while speaking | Muted/wrong microphone or low input level |
| Sent counts match, speech levels present, no partial/final text | Inspect server events/format; non-zero noise alone does not establish intelligible speech |
| `AudioQueueOverflow` | Connection/send path fell behind the bounded queue; request fails instead of silently losing audio |

### Exact STT retest

1. Close the running Pointly process. In **Windows Settings → System → Sound → Input**, choose the intended default microphone, unmute it and confirm its input-level meter responds to your voice. Pointly leaves these settings under your control.
2. In the same PowerShell that has `ELEVENLABS_API_KEY`, run:

   ```powershell
   Remove-Item Env:POINTLY_DEBUG_WALKTHROUGH -ErrorAction SilentlyContinue
   $env:POINTLY_VOICE_MODE = "true"
   dotnet run --project Pointly.App/Pointly.App.csproj -c Debug --no-build
   ```

3. Keep Excel foreground. Press Ctrl+Space once. Speak “How do I create a PivotTable?” for roughly 5–8 seconds, then press Ctrl+Space once to finalize. Do not click Pointly while recording.
4. Check the selected device/mute log, non-zero speech levels, `session_started`, partial events, and matching `MicSummary`/`SttAudioSummary` counts. `SttCommitSent` must precede the final committed event. A nonempty final proceeds to the existing request pipeline.
5. Repeat once while silent. An empty final must show the check-microphone status, then allow another activation. If a speaking attempt is still empty, copy the safe summary/event lines; do not save or share audio/base64 or credentials.

Automated coverage uses synthetic PCM and a fake WebSocket. It tests format/level calculations, immediate forwarding, FIFO drain before commit, waiting for final, early commits, server failures, empty transcript behavior, cancellation and clearing sent buffers. It requires neither recording nor a live ElevenLabs request. Microphone input and network behavior still need the above live retest. No audio is written to disk, and no changes were made to grounding, verification, walkthrough or TTS implementations.
