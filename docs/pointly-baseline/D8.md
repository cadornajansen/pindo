## Architecture and ownership

The application still uses the existing tutor, D3 foreground-window capture, UIA-first grounding and D6 verification. MainWindow connects those services to the presenter; it contains no provider-specific voice transport or drawing policy. Existing predefined Excel intent mapping is preserved; other spoken questions are still one-shot guidance, not generated lessons.

- `GuidancePresenter`: owns presentation identity, current instruction/physical target, one-time narration and cancellation. It never declares a step complete. `TargetContextWatcher` independently binds that presentation and its verifier to a window snapshot.
- `BuddySurface`: a monitor-sized WPF surface with an original mint pointer mascot, passive bubble and six local annotation styles. Pointer is the ordinary default; point targets use rings. Physical coordinates convert to monitor-local DIPs only here. A 280 ms glide replaces the previous animation and respects Windows animation settings. Idle/hidden surfaces have no animation loop.
- `TrayShell`: availability, summon/dismiss, mic mute, explicit interruption, diagnostics and exit. Startup creates a hidden diagnostics HWND for hotkeys; no microphone opens at startup. A named mutex prevents competing instances.
- `VoiceSession`: same D7 service, extended in `VoiceSession.Persistent.cs`. `VoiceActivity` separately reports active session, microphone, processing, playback and mute. D6 verification remains independent: speaking and waiting for the user may coexist.
- `ElevenLabsSpeechToText`: supports documented manual transport for the retained D7 tests and normal D8 VAD transport. `WindowsAudioCapture` and the fixed WinMM default-device/PCM pipeline are unchanged.
- `ClickVerificationService` / `StepVerificationCoordinator`: still own click, key, text and post-action UIA completion. No audio callback advances a walkthrough.
- `UiaWorkScheduler`: one background MTA worker, two pending jobs maximum. Cancellation/timeouts release the caller, not the execution slot. A hung provider cannot cause replacement threads to accumulate. Restart Pindo if a provider remains wedged; no paid retry loop is added.

## Normal hotkeys and debug precedence

| Input | Behavior |
|---|---|
| Ctrl+Space while hidden | Show buddy near current cursor and summon persistent voice; respect tray mute |
| Ctrl+Space while visible | Dismiss; cancel voice, current request, walkthrough, verifier, narration and visuals |
| Ctrl+Alt+Space while visible | Cancel/replace current turn and guidance, stop playback, keep buddy, listen again (unless muted) |
| Ctrl+Alt+Space while hidden | No action |
| Tray microphone mute | Stop capture; keep session/guidance available; unmute resumes listening |
| Close diagnostics | Hide diagnostics; use tray Exit to quit |

Normal D8 **does not** use a second Ctrl+Space to commit speech. Silence commits it.

DEBUG precedence: `POINTLY_DEBUG_PREVIEW=true` shows all six annotations locally; Ctrl+Space dismisses preview. Otherwise `POINTLY_DEBUG_WALKTHROUGH=excel-pivottable` or `excel-search` retains the deterministic hotkey walkthrough workflow. This debug mode bypasses normal voice-toggle semantics; use tray Exit to terminate it. Remove these overrides for normal D8.

For standalone non-voice D5/D6 regression, set `POINTLY_VOICE_MODE=false`. Ctrl+Space then keeps the earlier single-target/cancel behavior. `POINTLY_DEBUG_FORCE_VISION=true` and `POINTLY_DEBUG_GROUNDING_QUERY` retain their existing meanings; forced vision is ignored for UIA-only text-entry verification. Nova is still opt-in via `POINTLY_GROUNDING_PROVIDER=nova`; no automatic provider fallback was added.

## Voice protocol, echo and lifetime

Normal STT connects to `wss://api.elevenlabs.io/v1/speech-to-text/realtime` with `model_id=scribe_v2_realtime`, `audio_format=pcm_16000`, `commit_strategy=vad`, `vad_silence_threshold_secs=1.0`, `include_timestamps=false`. Language is not forced to English. Audio remains 16 kHz signed PCM16 little-endian mono, normally 100 ms / 3200 bytes per chunk; the existing bounded 32-chunk microphone queue is preserved.

The send format remains `input_audio_chunk`, `audio_base_64`, `sample_rate=16000`, `commit=false`. In VAD mode no manual empty commit is sent. The provider receiver can emit multiple committed segments and keeps empty segments from invoking the tutor. `committed_transcript_with_timestamps` is an enriched copy and never triggers a second request. Sequence/connection/session identity rejects stale callbacks; matching text in a new utterance is intentionally allowed.

Pindo uses safe half-duplex audio. On accepting a question, it closes the listening epoch and releases the microphone before processing or speech. Before queued walkthrough narration it stops capture and closes that STT connection; narration waits if partial speech is active. After native playback has actually drained (`PlaybackStopped`, not just an empty software buffer), it opens a fresh listening connection inside the **same Pindo session**. This isolates TTS from future transcripts. The connection restart adds latency but prevents accumulated speaker audio from becoming a later question.

There is no acoustic echo cancellation or automatic spoken barge-in. Use Ctrl+Alt+Space. Speech during TTS/processing is deliberately not recorded. TTS network/playback ownership is serialized; cancellation stops playback and waits for device cleanup before another microphone owner proceeds. Narration has a 45-second bound; processing has a 60-second bound. Errors stop the affected operation without an endless reconnect loop. If voice fails and the buddy remains visible, dismiss and summon again.

The presenter cancels narration on step completion/replacement. Each presentation requests speech once. Verification is armed when the target appears, without waiting for TTS. A new accepted question replaces existing guidance through the same MainWindow query path.

Workstation lock, suspend and session shutdown cancel active voice/guidance. Unlock does not automatically resume the microphone.

Official protocol references checked during implementation: [ElevenLabs realtime STT](https://elevenlabs.io/docs/api-reference/speech-to-text/v-1-speech-to-text-realtime), [NAudio PlaybackStopped](https://github.com/naudio/NAudio/blob/master/Docs/PlaybackStopped.md), [WinEvent hook lifetime](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-setwineventhook).

## Window freshness, focus and privacy

WinEvent notifications are debounced 120 ms; known layout invalidation disarms geometry immediately. Move/resize, DPI change, minimize/closure and changed foreground cancel stale targets. The app asks for a fresh question rather than automatically spending another model request. Click-time freshness is captured before the click reaches the application, so a correctly clicked dialog may close before its queued verification callback runs. Later walkthrough windows must share the original root owner and process; a same-process unrelated workbook/window is insufficient.

Typing/key steps keep their intended UIA identity and tolerate control-layout notifications; top-level window geometry/focus rules still apply. Custom-rendered apps that emit no accessibility layout event can change internal content without a detectable invalidation. D8 does not continuously capture or semantically verify their layouts.

Overlay HWNDs use NOACTIVATE, TOOLWINDOW, TRANSPARENT and LAYERED, plus explicit native no-activate/hit-test responses. Live cross-process click-through still requires acceptance testing. Each overlay surface uses its own monitor origin and DPI; negative desktop coordinates remain valid. A target spanning monitors is presented on its center monitor, so annotations may clip at that monitor boundary. Very large regions may leave insufficient room to avoid all overlap; the placement policy chooses the least overlap within the work area.

Pindo's own process is rejected as foreground/UIA input. The overlay requests WDA_EXCLUDEFROMCAPTURE; it is also temporarily hidden around D3 foreground-window capture as a defensive fallback. Capture restoration uses only the current presentation, including after replacement/dismissal. Neither audio nor screenshots are written locally by default. `POINTLY_CAPTURE_DEBUG_DIR` remains an explicit screenshot-to-disk opt-in; remove it for normal use. Diagnostics are capped at 300 in-memory lines. Instructions/transcripts may be displayed but are not written to telemetry. Raw provider bodies and UI values are withheld.

Memory-only local handling does not establish zero retention by cloud providers. This developer build still needs user-provided environment credentials. **Public distribution is blocked until shared credentials are replaced by a secure production access path.** No backend/accounts were added.

## First live test

Save your ElevenLabs key **once** for your Windows user (hidden prompt; no key in source or shell history):

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File C:\Development\apps\Pointly\scripts\Set-ElevenLabsKey.ps1
```

STT and TTS read `ELEVENLABS_API_KEY` from the process first, then directly from the saved Windows user environment when the process value is absent/blank. They re-read it for each request, so a saved key works even if the launcher inherited an older environment. A non-empty process override takes precedence. User environment variables persist across terminal sessions/reboots; they are local developer configuration, not an encrypted secret vault. The setup script does not store audio or write a key file. OpenRouter's existing process/user lookup and all other provider behavior are unchanged.

Exit any older Pindo build through its tray before launching the updated build. With your existing tutor/grounding credentials available:

## Measurements and test interpretation

Safe instrumentation covers summon-to-visible, target-ready-to-visible, microphone startup, STT connect, committed transcript-to-processing, UIA collection/resolution, capture/encoding, model request, guidance total, first TTS audio bytes, playback stop request and actual playback stopped. Model and action-wait durations remain separate.

Real user-visible before/after latency: **not measured**. Realtime STT supplies no precise speech-end event in this configuration, so `SpeechEndToFinalMs=Unavailable` is reported rather than estimating it from a partial transcript. `TtsTimeToFirstAudioMs` measures first returned PCM chunk, not acoustic output. No latency improvement claim is made.

Automated coverage includes actual offscreen WPF bitmap rendering for all primitives, animation replacement/stop, negative coordinates/scales, original D6 state transitions, bounded MTA scheduling/cancellation, persistent speech lifecycle and 50 mocked cycles. It does not prove native clicks reach another app, microphone fidelity, cloud grounding accuracy, or speaker-room echo behavior.

Published-process startup smoke: process remained alive with zero visible application windows; the probe did not activate voice. First focus sample changed during the observation window, so no focus conclusion was drawn from it. A second probe confirmed the foreground stayed in Chrome on the same HWND and never belonged to Pindo. The test-created process was stopped after each probe; this was not a graceful tray-exit test, a microphone test, or a full manual acceptance run.

## Release and opt-in packaging

Ordinary builds/tests do not include the packaging project:

```powershell
dotnet build Pointly.sln -c Debug
dotnet test Pointly.sln -c Debug
dotnet build Pointly.sln -c Release
dotnet test Pointly.sln -c Release
dotnet publish Pointly.App/Pointly.App.csproj -c Release -r win-x64 --self-contained true -p:PublishTrimmed=false -p:PublishAot=false -o artifacts/publish/win-x64
```

Publish output: `C:\Development\apps\Pointly\artifacts\publish\win-x64\Pointly.App.exe`. This is a folder deployment; keep its DLLs/native runtime alongside it. No trimming/AOT. It is not a signed installer. Launch it directly from your configured PowerShell to inherit that process environment.

The separate project `packaging/Pindo.Package/Pindo.Package.wapproj` is intentionally outside `Pointly.sln`. It uses desktop full-trust entry-point substitution for the referenced WPF EXE, original generated Pindo icon assets and version 0.8.0.0. Minimum package OS is Windows build 26100, matching the existing target. No auto-start, admin requirement or `uiAccess=true`. Capabilities are desktop full trust and microphone.

Requirements: Visual Studio with .NET desktop development, Windows Application Packaging Project/DesktopBridge targets, Windows SDK 10.0.26100.0 and an MSBuild version that supports the .NET 10 SDK. Use Visual Studio MSBuild, not `dotnet build`, for WAP. See [Microsoft's WPF packaging guidance](https://learn.microsoft.com/en-us/windows/msix/desktop/vs-package-overview).

```powershell
.\packaging\Build-Msix.ps1
# Only if you already supplied an appropriate development signing certificate:
.\packaging\Build-Msix.ps1 -CertificateThumbprint 'YOUR_CERTIFICATE_THUMBPRINT'
```

Expected package output: `artifacts/msix/`. The default is unsigned and **not normally installable**. A supplied certificate must be available to the signing tool, valid for code signing, and match `Publisher="CN=Pindo Development"` (or deliberately update publisher to match your certificate). Trust/install is an explicit developer action; this task does not create, import or trust a certificate. Private keys, .env files and artifacts are ignored by Git and not included as package content.

Actual packaging attempt stopped at: **“No Visual Studio MSBuild installation was found. dotnet build does not provide DesktopBridge packaging targets.”** No MSIX was produced, signed, installed or submitted. The project must be validated on the required toolchain. A Start-menu launched package will not inherit variables from an unrelated PowerShell terminal. For local packaged testing, configure developer-owned per-user environment credentials before launching from a refreshed login/session, or use an explicitly configured development launcher. Do not embed shared keys in the package. This remains a developer build, not turnkey public distribution.
